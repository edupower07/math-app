# 紹介動画 v4（Remotion・90秒）デザイン仕様

「名探偵！かずのひみつ」SNS紹介動画の**絵づくりの決定事項**。
`tools/video/remotion/` の実装はこの文書に従う。実際の見た目は
`npm run stills`（後述）で書き出したキーフレームで確認できる。

---

## 1. この版で新しく分かったこと

### アプリは「全画面に敷ける絵」ではない

実測すると、アプリのカラムは **940 × 1122px の縦長**、その中の捜査パネル
（`.case-paper`）は **912 × 709.5px** だった。つまり：

| 収録サイズ | 結果 |
|---|---|
| 1920×1080（16:9） | 左右に 490px ずつ余る |
| 1080×1920（9:16） | 下に 800px 余る |

v1〜v3 が「紙芝居」「静止画をつないだ感じ」に見えた原因の一端はここにある。
アプリを全画面に引き伸ばすか、余白を放置するかの二択になっていた。

### → 「机の上に置かれた捜査ファイル」として扱う

余白を**捜査デスクとして使い切る**。アプリは机に置かれた一枚の書類で、
まわりに証拠カード・容ぎ者カウンタ・注釈を並べる。

これで3つ解決する。

1. 16:9 の左右が意味のある情報で埋まる
2. アプリの世界観（レトロ捜査ファイル）と演出が地続きになる
3. **9:16 は同じ部品の配置替えで作れる**（左右→上下に積む）ので、
   縦版のために撮り直す必要がない

## 2. デザインシステム

すべて `src/styles.html` の `:root` から取っている。動画とアプリで
色と書体を完全に一致させ、「アプリの続き」に見せるのが狙い。

### 色（`src/theme.ts` の `C`）

| 役割 | 値 | 用途 |
|---|---|---|
| 机（地色） | `#1e1913` / `#2b241c` | 全カットの背景 |
| 古紙 | `#f2e4c6` | 証拠カード・パネル |
| 金 | `#c79a3f` / `#ffd36a` | 強調・数字・罫 |
| スタンプ赤 | `#b03a2e` | 解決・決着の色 |
| マニラ | `#cda76a` | 注釈・小見出し |

学習カテゴリ色はアプリの手がかりカードと同一：
偶数奇数 `#2f6f8f`／倍数 `#5f7a34`／約数 `#b0402f`／公倍数 `#6d4a86`／
公約数 `#c47a24`／基本 `#7a6a4c`。

参考動画の「黒 × 金 × 赤」は、この配色にそのまま重なる。完全な黒ではなく
温かみのある机色を使うのは、対象が小学5年生だから。

### 書体（`F`）

| 用途 | 書体 |
|---|---|
| 見出し・ロゴ | Zen Antique（明朝） |
| 数字・％・事件番号 | Special Elite（タイプライター） |
| テロップ・本文 | Yusei Magic |
| UI再現パーツ | Zen Maru Gothic |

**数字は必ず Special Elite**。カウンタ・％・FILE番号がタイプライター体で
揃うと、書類としての説得力が出る。

### レイアウト（`L`、16:9基準）

```
┌─────────────────────────────────────────────┐
│ FILE No.002  捜査 ── ひみつの数をさがせ        │ ← 章ラベル（左上）
│ ┌───────────────────┐   容ぎ者 25 人          │ ← 数字（右上）
│ │                   │   ▓▓▓▓▓░░░░░░          │ ← 絞り込みバー
│ │   現場パネル        │   ┌──────────────┐    │
│ │   940 × 731       │   │ 偶数･奇数 証拠① │    │ ← 証拠カード
│ │                   │   └──────────────┘    │
│ └───────────────────┘         ※注釈         │
│        ┌────────────────────────┐            │
│        │ ③ テロップ（常時）        │            │ ← 字幕バー
│        └────────────────────────┘            │
└─────────────────────────────────────────────┘
```

- 左 = **現場**（アプリ）／右 = **捜査ボード**（数字・証拠・注釈）
- 9:16 では左右を上下に積み替える。部品は共通

## 3. 参考動画から採り、この教材に置き換えたもの

| 参考動画の型 | この動画での置き換え |
|---|---|
| 画面下にナレーション字幕バーが常時 | そのまま採用。**90秒間ずっと出す** |
| 巨大な金の数字 | 「容ぎ者 ◯人」カウンタ |
| ％カウントアップの進捗バー | 絞り込みバー（50→25→12→1）＋「一意化率100%」 |
| 極太明朝タイトル＋赤影 | つかみと章の変わり目だけ。乱発しない |
| 小さな「※」注釈 | 教材としての但し書きに使う（後述） |
| ロゴがドンと着地 | そのまま採用（`LogoLanding`） |
| 「1分でわかる」冠フォーマット | 「FILE No.00X」の事件ファイル番号で章を刻む |

### 字幕バーは音声の有無に関係なく必須

ナレーションは未決だが、**テロップ文言はそのままナレーション原稿として
書く**。こうしておけば、あとで pyopenjtalk の音声を足すときに文章を
書き直さずに済むし、無音のまま出しても意味が通る（SNSはミュート視聴が大半）。

### 「※」注釈はこの教材と相性が良い

参考動画では小ネタでテンポを作っていたが、ここでは**教材としての誠実さ**に
使える。「※自動では消えません」「※3000回×検証ずみ」のように、
先生が気にする点を短く添える。

### 収録に使う事件（検証済み）

**犯人 = 24／現場 1〜50**、手がかりは3枚。

| 順 | 手がかり | カテゴリ（色） | のこる容ぎ者 |
|---|---|---|---|
| ① | 犯人の数は 偶数 | `parity`（青） | 50 → **25** |
| ② | 犯人の数は【6】の倍数 | `multiple`（緑） | 25 → **8** |
| ③ | 一の位は【4】 | `basic` / ones（セピア） | 8 → **1** |

この3枚で 24 に一意に絞れることは確認済み。カテゴリが青→緑→セピアと
散るので、証拠カードの色が3枚とも変わって画面が単調にならない。

> 手がかりに**奇数**を使ってはいけない。24 は偶数なので破綻する。
> （初稿でこれを取り違えていた。数字を変えるときは必ず一意性を検算すること）

## 5. 役割分担を変える（重要）

v3 までは `director.js` がテロップ・チップ・カードを**ページに注入してから
録画**していた。Remotion を使う以上、これはやめる。

| | v3まで | v4（今回） |
|---|---|---|
| ズーム | director.js | **director.js**（収録時にしかできない） |
| カーソル | director.js | **director.js**（同上） |
| テロップ | director.js | **Remotion** |
| 証拠カード・カウンタ・注釈 | director.js | **Remotion** |
| スポットライト・スタンプ | アプリ／director.js | **Remotion**（位置は計算で当てる） |

理由：テロップが焼き込まれていると、**言い回しを直すたびに録り直し**になる。
分離しておけば、文言もタイミングも尺も、録画素材はそのままで何度でも直せる。

→ 次の収録では **director.js は「素の操作」だけを撮る**。
`telop()` / `chip()` / `card()` の呼び出しは録画スクリプトから外す。

## 6. 実装メモ

### 座標は計算で出す（目分量で置かない）

スポットライトを「24番のマス」に当てるような処理は、`FileCard.tsx` の
`PANEL` / `cellRect()` / `panelToFrame()` を使う。素材内の実測値
（パネル原点・グリッド矩形）から算出しているので、カードの幅や位置を
変えても追従する。

### 収録のしかた（`tools/video/recorder_v4.py`）

絵コンテの1カット＝1ファイルで撮る。長回しにすると尺を調整するたびに
全体のフレーム位置がずれるため。

```bash
pip install playwright imageio-ffmpeg
python3 tools/video/recorder_v4.py          # 全カット
python3 tools/video/recorder_v4.py s06 s09  # 指定カットだけ撮り直し
```

**捜査コア（#4〜#8）は収録時にズームしない。** 素の 1920×1080 で撮り、
Remotion 側で現場パネル（`504,125.5` / `912×709.5`）を切り出して机に置く
（`PanelFootage`）。切り出し 912px → 配置 940px なので拡大は 1.03 倍で、
画質は実質そのまま。寄り・引きを後から変えられるので尺の調整で絵が破綻しない。

**寄りのカット（#9 解決／#11 図鑑／#12〜#14）だけは収録時にズームする**
（`FullFootage` でそのまま全画面）。CSS transform は DOM ごと拡大するので
文字がベクタのまま鮮明で、あとから映像を引き伸ばすのとは品質が違う。

> `s11` は当初「探偵ランクUP」を撮る想定だったが、バッジ数が昇格の閾値を
> またがず昇格モーダルが出なかった。実際に撮れている**解禁マップ**に
> カットの主題を寄せてある。ランクアップを見せたい場合は `APP.badges` を
> 閾値の直前に設定すること。

### ハマったところ

- **`Shake` は必ず `AbsoluteFill` で返す。** `transform` を持つ要素は
  `position:absolute` な子孫の包含ブロックになるため、素の `div`
  （高さ auto = 0）で包むと中の `inset:0` が 0×0 に潰れ、
  スポットライトが**丸ごと消える**。
- **`Easing.quint` は存在しない。** `Easing.poly(5)` を使う。
- **スポットライトの暗さは 0.8 まで。** これ以上落とすと現場そのものが
  見えなくなり、「何を絞り込んだのか」が伝わらない。
- **Remotion のレンダーに `/opt/pw-browsers/chromium` は使えない。**
  旧ヘッドレスが削除済みで起動に失敗する。
  `chromium_headless_shell-1194/chrome-linux/headless_shell` を指すこと
  （`remotion.config.ts` で設定済み）。
- **Playwright 同梱の ffmpeg で mp4 は作れない。** VP8/webm 専用ビルドで
  `libx264` を持たない。`imageio-ffmpeg` の完全版を使うこと
  （`recorder_v4.py` の `ffmpeg_exe()`）。**変換元の webm を消す前に
  変換の成否を必ず確認する**（一度これで素材を失って撮り直した）。

### フォント

`fonts.googleapis.com` はネットワーク的には許可されているが、
**サンドボックス内の Chromium は `HTTPS_PROXY` を読まない**ため直接は引けない。
（v3 のメモにあった `ERR_CONNECTION_RESET` の真因はこれで、
ドメイン遮断ではなかった。）

→ `scripts/fetch-fonts.py` で先に `public/fonts/` へ落とし、
`@font-face` でローカル参照する。woff2 は 489ファイル・約9.6MB あるので
git には入れていない（`.gitignore` 済み）。

```bash
cd tools/video/remotion
python3 scripts/fetch-fonts.py   # 初回のみ
npm install
npx remotion still KF3-Investigate out/KF3-Investigate.png --frame=60
```
