# ナレーション台本（90秒版）

読み上げ音声を用意するときは、この台本のとおりに録ってください。
文言は動画のテロップと**同じ**です（無音でも意味が通るよう、
最初からテロップ＝ナレーション原稿として書いてあります）。

---

## 渡し方

**おすすめは「カットごとに1ファイル」**です。ファイル名の数字がカット番号に
対応していれば、こちらで所定の位置に置きます。あとから1行だけ録り直したい
ときも、その1ファイルを差し替えるだけで済みます。

```
01.mp3  02.mp3  03.mp3  …  16.mp3
```

**1本の通しファイルでも大丈夫**です。その場合は、**行と行のあいだに1秒ほど
はっきり間を空けて**読んでください。無音を手がかりに自動で切り分けます。
間が詰まっていると切り分けを誤るので、そこだけ気をつけてください。

形式は mp3 / wav / m4a のどれでも構いません。音量は揃えなくて大丈夫です
（こちらで -16 LUFS に統一し、BGM を自動で下げます）。

---

## 台本

「秒」は動画上でその行が出るタイミング、「尺」はそのカットの長さです。
**尺に収まる範囲で自然に**読んでいただければ、多少前後してもこちらで調整します。

| # | 秒 | 尺 | 読む文 |
|---|---|---|---|
| 1 | 0:00 | 3.0 | 小5算数「整数の性質」。つまずきやすい単元です。 |
| 2 | 0:03 | 4.0 | その授業、「事件」にしてみませんか。 |
| 3 | 0:07 | 4.0 | 数の世界の事件簿へ、ようこそ。 |
| 4 | 0:11 | 5.0 | ルールは1つ。かくれた「ひみつの数」を当てる。 |
| 5 | 0:16 | 5.0 | 手がかりを1枚ずつ調べて、犯人を追いつめる。 |
| 6 | 0:21 | 9.0 | 合う数は自分でぜんぶタップ。ここが考えどころです。 |
| 7 | 0:30 | 7.0 | 手がかりを重ねるほど、容ぎ者は減っていく。 |
| 8 | 0:37 | 6.0 | そして、のこったのは—— |
| 9 | 0:43 | 6.0 | 真犯人は24。使った手がかりは、たった3つ。 |
| 10 | 0:49 | 6.0 | 手がかりを重ねれば、論理だけでたどりつけます。 |
| 11 | 0:55 | 6.0 | 解決するほど探偵レベルが上がり、使える手がかりが増える。 |
| 12 | 1:01 | 6.0 | 公倍数・公約数は、重ねて目で見て確かめる。 |
| 13 | 1:07 | 6.0 | 自分で挑戦状をつくって、なかまに解かせる。 |
| 14 | 1:13 | 6.0 | クラスみんなでの対戦にも。 |
| 15 | 1:19 | 6.0 | 導入からまとめまで、これ1つで。 |
| 16 | 1:25 | 5.0 | 進捗はスプレッドシートに。クラスでも、ひとりでも。 |

読み全体で約 55〜65秒です。各行のあいだに自然な「間」が入る想定なので、
早口にする必要はありません。

## 読み方のメモ

- **#8「そして、のこったのは——」**は、あえて言い切らずに次のカット（解決）へ
  つなぐところです。語尾を少し引いてください。
- **#9「真犯人は24」**が山場です。ここだけ一段はっきりと。
- **#2「事件」**、**#6「自分でぜんぶタップ」**、**#10「論理だけ」** は
  テロップでも金色で強調しています。軽く置くように読むと画と揃います。
- 数字（24・3つ・1つ）は聞き取りやすく。

---

## こちらでやること

音声を受け取ったら、次を自動で処理します。

1. **音量を -16 LUFS に統一**（BGM は -20 LUFS なので、声が4LU上に出る）
2. **BGM を声の区間だけ自動で下げる**（ダッキング。0.35秒かけて32%まで）
3. 各行を対応するカットの頭に配置

実装は `remotion/src/Soundtrack.tsx` の `NARRATION` に1行ずつ足すだけです。
音量調整は `remotion/scripts/build-audio.py vo <ファイル>` が行います。

## 合成音声で仮に作る場合

オフラインの `pyopenjtalk` が使えます（声は Mei・女性1種類のみ）。
明瞭ですがやや機械的なので、仮当てには十分でも、本番の可否は要判断です。

```python
import pyopenjtalk, soundfile as sf
x, sr = pyopenjtalk.tts("小5算数、整数の性質。つまずきやすい単元です。")
sf.write("01.wav", (x / 32768.0).astype("float32"), sr)
```

## 受領済み（2026-07-25）

1本の通しファイル（79.25秒 / 24kHz mono / -21.3 LUFS）を受領。
無音を手がかりに16行へ自動分割し、各行を -16 LUFS に揃えて配置した。

分割は「長い無音を上から15個」では破綻した（1行が13秒になる等）。
台本の文字数から期待尺を出し、**候補の無音のうち発話速度のばらつきが
最小になる15個を動的計画法で選ぶ**方式にしたところ、全16行が
3.6〜7.3文字/秒に収まった。

読みが台本より長かったため、**カット割りを声に合わせて組み直した**
（例：#1 は 3.0秒 → 7.0秒）。総尺は90秒のまま。

> **この音源は `-ss` を `-i` の前に置くと40秒以降が読めない**（WAVヘッダの
> 問題と思われる）。切り出しは必ず `-i` の後に `-ss` を置くこと。
