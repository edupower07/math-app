# 🔍 名探偵！かずのひみつ

小学5年生 算数「整数の性質」（偶数・奇数／倍数／約数／公倍数／公約数）の
導入〜まとめで使える、**レトロ捜査ファイル風の学習 Web アプリ**です。

証拠（手がかり）を1つずつ調べ、**合わない数を現場（数表）から消していき、自分で犯人＝「ひみつの数」をタップして告発する**推理ゲーム。単元の進み（フェーズ）に合わせて使える手がかりの種類と現場のはんいが増えていきます。

- **フロントエンド**：HTML / CSS / JavaScript（GAS の HTML Service で配信）／Google Fonts（Zen Antique 等）で捜査ファイルの世界観
- **バックエンド**：Google Apps Script
- **データ保存**：Google スプレッドシート（作問データ・グループ対抗スコア・**児童ごとの進捗**）
- スマホ・タブレットのブラウザに対応したレスポンシブ設計

---

## ゲームの核（自分で考えて絞り込む × かならず解ける）

**遊び方**：手がかりを1つ調べる → その手がかりに**合う数を自分で全部タップ**（ドラッグ選択も可）→ 合わない数が消え、生き残った**犯人候補がだんだん濃く**なる → 候補が1人になったら真犯人！ 少ない手がかりで見やぶるほど「⚡するどい推理」ボーナス。

> 自動では消えません。「偶数」と出たら偶数のマスを自分で見つけてタップする＝**手を動かして考える**設計です。合う数を全部えらぶまで次の手がかりに進めず、選び忘れがあればヒントが出ます。

手がかりは2種類あります。

- **基本の手がかり（いつでも使える）**：`◯より大きい/小さい`・`一の位`・`けた数`
- **単元の手がかり（フェーズ／探偵レベルで解禁）**：`偶数・奇数`→`倍数`→`約数`→`公倍数`→`公約数`

問題生成は「単元の手がかりを優先しつつ、基本の手がかりで**必ず容ぎ者が1人に絞れる**」ことを保証します（全フェーズ3000回×検証で一意化率100%）。
これにより、**偶数・奇数だけのフェーズでも“最後は運ゲー”にならず**、論理だけで犯人を特定できます。

### 探偵レベルで自分の学習を進める

先生の設定した**フェーズはクラス共通の土台**。いっぽうで、事件を解決して**探偵レベル（バッジ）が上がると、その子は先の手がかりを個人的に解禁**できます。

- **作問モード**：使える手がかりは「探偵レベルで解禁ずみ」のものだけ（未解禁は🔒で「あと◯事件で解禁」と表示）。
- **🎓 じぶんレベルで挑戦**：通常の捜査でも、自分のレベルに合わせた手がかり・はんい（バッジ10で1〜100）で挑戦できるトグル。

### 用語じてん（📖）

「約数って何だっけ？」を、**ホーム画面からも捜査中からも**確認できます。内容は教科書の定義に準拠（偶数・奇数・倍数・公倍数・最小公倍数・約数・公約数・最大公約数）。

## 画面と機能

| # | 画面 | 内容 |
|---|------|------|
| 1 | **捜査（ひみつの数当て）** | 現場（1〜50 / 1〜100）。手がかりを調べ、**合う数を自分で全部タップ**して絞り込む（自動では消えない）。全部えらぶまで次に進めず、選び忘れはヒント。候補が濃くなり、1人になったら**スポットライト＋「解決」スタンプ演出**で真犯人を確定。 |
| 2 | **手がかり図鑑・ランク** | 手がかりの**解禁マップ**（基本＝いつでも／単元＝フェーズ＆探偵レベルで解禁、未解禁は🔒＋あと何事件で解禁か）。探偵ランク・解決数・最少手がかり数。フェーズ6で「名探偵 認定試験」解禁。 |
| 3 | **重ねて分析（公倍数・公約数）** | 2数 A・B の倍数（約数）を色分けして重ね、公倍数（公約数）を強調。最小公倍数・最大公約数を問う設問つき。50⇄100 切替時に「LEVEL UP！」演出。 |
| 4 | **挑戦状づくり（作問）** | 「ひみつの数」と手がかり2〜4個を組み立て。**使える手がかりは探偵レベルで解禁**（未解禁は🔒表示）。追加のたびに「容ぎ者◯人」をリアルタイム表示し、みんなの未解決事件に保存。 |
| 5 | **グループ対決** | 教員がスクリーンに手がかりを1つずつ提示。回答班は各端末の現場を操作し、犯人をタップ。早さ・使用手がかり数でスコア加算し、スコアボードに表示。 |
| 6 | **用語じてん** | 教科書準拠の用語説明。ホームからも捜査中からも開ける。 |

## ファイル構成

```
src/
├── appsscript.json   … GAS マニフェスト
├── Code.gs           … サーバーサイド（配信・スプレッドシート読み書き）
├── index.html        … 画面の HTML（全画面を1ページに内包）
├── styles.html       … CSS（名探偵テーマ）
└── app.html          … フロントエンドの JavaScript（ゲームロジック一式）
```

`index.html` は GAS の `include()` で `styles` / `app` を読み込みます。

## デプロイ手順

### 方法A：Google Apps Script エディタに手貼り

1. [script.google.com](https://script.google.com) で新規プロジェクトを作成。
2. `src/Code.gs` の中身を `コード.gs` に貼り付け。
3. `＋` →「HTML」で `index` / `styles` / `app` の3ファイルを作り、
   それぞれ `src/index.html` / `src/styles.html` / `src/app.html` の中身を貼り付け
   （ファイル名は拡張子なしで `index`・`styles`・`app`）。
4. マニフェスト（`appsscript.json`）を表示する設定を ON にし、`src/appsscript.json` の内容に合わせる。
5. 「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」。
   - 実行するユーザー：**自分**
   - アクセスできるユーザー：**組織内の全員**（`appsscript.json` の `access` は運用に合わせて調整）
6. 発行された URL を児童に配布。

### 方法B：clasp（コマンドライン）

```bash
npm install -g @google/clasp
clasp login
clasp create --type webapp --title "名探偵かずのひみつ" --rootDir ./src
clasp push
clasp deploy
```

> `.clasp.json` の `rootDir` を `./src` に向けると、`src/` 配下の
> `.gs` / `.html` / `appsscript.json` がそのままアップロードされます。

### スプレッドシートについて

- 初回アクセス時に、必要なシート（`problems` / `group_scores` / `progress` / `config`）が
  **自動で作成**されます（手動セットアップ不要）。任意で `setup()` を実行しても構いません。
- スタンドアロン運用の場合は専用スプレッドシートが自動生成され、その ID が
  スクリプトプロパティ `SPREADSHEET_ID` に保存されます。
- コンテナバインド（スプレッドシートに紐づけて作成）した場合は、そのシートが使われます。

### データ構造

| シート | 列 |
|--------|----|
| `problems` | id, secret, range, hints_json, author, candidates, created_at |
| `group_scores` | id, session, group_name, score, hints_used, time_sec, created_at |
| `progress` | user_id, name, badges, rank, solved, best_clues, unlocked_json, updated_at |
| `config` | key, value（`phase`：単元フェーズ、`groupSession`：対抗戦のセッション名、`teacherPass`：先生ページのパスワード） |

### 記録はちゃんと残る？（データの永続化について）

**はい。児童ごとの記録はスプレッドシートに永続保存され、毎回消えることはありません。**

- Google Workspace で公開（このリポジトリの `appsscript.json` は `access: DOMAIN`）すると、
  サーバー側の `getMe()` が `Session.getActiveUser().getEmail()` で**アクセス中の児童のメール**を取得します。
- 進捗（バッジ・ランク・解決数・最少手がかり）は、そのメールを `user_id` として `progress` シートに保存。
  だから**別の端末でログインしても、同じ記録が続きます**（端末依存の localStorage ではなくクラウドが正）。
- localStorage はあくまで**オフライン時のキャッシュ**として併用し、ログインできれば必ずスプレッドシートを優先します。
- メールが取れない構成（アカウント無し・匿名公開）では、名前をキーにしたフォールバックで動作します。

> ⚠️ 記録を残すには「ウェブアプリのアクセス」を **組織内** にし、児童が学校の Google アカウントで
> アクセスする必要があります（匿名公開だとメール識別ができません）。

## 教員向け：せんせい設定ページ

ホーム →「せんせい設定」でできること（画面上部にも説明を表示）：

1. **単元フェーズの切替（クラス共通）**：現在のフェーズ（1〜6）を選ぶと、使える単元手がかりと現場のはんい（50 / 100）が児童全員に反映（`config` シートに保存）。
2. **自分で先へ進みたい子への対応**：フェーズはクラスの土台。事件を解決して探偵レベルが上がった子は、「作問」や「🎓じぶんレベルで挑戦」で先の手がかりを個人的に使えます（先生が個別に許可する必要はありません）。
3. **グループ対決のセッション名**：スコアボードの集計を分けられます。
4. **🔑 先生ページのパスワード**：この設定ページに**かんたんなロック**をかけられます（`config` の `teacherPass` に保存）。児童が誤って単元設定を変えないための教室向けゲートで、強固な認証ではありません。

どのフェーズでも「基本の手がかり（大小・一の位・けた）」はいつでも使えるので、
下記の単元手がかりと組み合わせて**必ず1人に絞れる**問題になります。

| フェーズ | 単元 | はんい | 追加で使える単元手がかり |
|---------|------|-------|------------|
| 1 | 偶数・奇数 | 1〜50 | 偶数・奇数 |
| 2 | 倍数 | 1〜50 | ＋倍数 |
| 3 | 約数 | 1〜50 | ＋約数 |
| 4 | 公倍数 | 1〜100 | ＋公倍数（LEVEL UP 演出） |
| 5 | 公約数 | 1〜100 | ＋公約数 |
| 6 | 名探偵認定 | 1〜100 | 全部混合＋認定試験 |

### 探偵レベルによる個人解禁（自己学習ルート）

| 手がかり | 個人解禁（解決した事件数） |
|---------|--------------------------|
| 偶数・奇数 | 最初から |
| 倍数 | 3 |
| 約数 | 6 |
| 公倍数 | 10（このとき現場も1〜100に） |
| 公約数 | 15 |

## スコア計算式（グループ対抗）

`app.html` の `Group.computeScore(timeSec, hintsUsed)` にまとめてあり、後から調整できます。

```
スコア = max(10, 100 + speedBonus - hintPenalty)
  speedBonus  = max(0, 60 - かかった秒数)   // 速いほど加点
  hintPenalty = 使ったヒント数 × 8           // ヒントが少ないほど高得点
```

## 開発メモ

- ゲームのヒント生成・数の性質判定は `app.html` の `Engine` にまとまっています。
- GAS 通信は `Server.call()` に集約。GAS 以外の環境（ローカルプレビュー等）では
  自動的に `localStorage` にフォールバックするため、ブラウザ単体でも動作確認できます。
